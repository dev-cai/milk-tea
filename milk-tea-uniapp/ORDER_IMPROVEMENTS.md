# 订单页面优化文档

## 优化内容

### 1. 移除配送地址选择 ✅
**原因：**
- 奶茶店不需要配送地址
- 用户到店自取或堂食

**修改：**
- 删除"收货地址"选择模块
- 添加"取餐方式"选择

### 2. 改为取餐方式选择 ✅
**新增功能：**
- 到店自取
- 堂食（需要输入桌号）

**UI设计：**
- 两个选项按钮切换
- 选中状态有渐变色高亮
- 堂食时显示桌号输入框

### 3. 移除配送方式选择 ✅
**原因：**
- 奶茶店不需要配送
- 简化订单流程

**修改：**
- 删除"配送方式"选择弹窗
- 删除配送费计算
- 改为显示"预计完成时间"

### 4. 添加余额支付扣减 ✅
**功能：**
- 余额支付前检查余额是否足够
- 余额不足时提示充值
- 支付成功后自动扣减余额
- 更新本地用户信息

**实现逻辑：**
```javascript
// 1. 检查余额
if (paymentMethod === 'balance') {
    if (currentBalance < order.totalAmount) {
        // 提示余额不足，跳转充值
    }
}

// 2. 支付成功后扣减
if (paymentMethod === 'balance') {
    const newBalance = currentBalance - order.totalAmount
    this.userInfo.balance = newBalance
    uni.setStorageSync('userInfo', this.userInfo)
}
```

## 支付流程优化

### 1. 余额支付流程：
```
1. 用户选择余额支付
   ↓
2. 检查余额是否足够
   ├─ 不足 → 提示充值
   └─ 足够 → 继续
   ↓
3. 显示确认支付弹窗
   - 显示订单金额
   - 显示当前余额
   ↓
4. 用户确认支付
   ↓
5. 创建订单
   ↓
6. 扣减用户余额
   - 计算新余额
   - 更新本地存储
   ↓
7. 显示支付成功
   ↓
8. 跳转订单列表
```

### 2. 其他支付方式：
```
1. 用户选择支付方式
   ↓
2. 显示确认支付弹窗
   ↓
3. 用户确认支付
   ↓
4. 创建订单
   ↓
5. 模拟支付成功
   ↓
6. 跳转订单列表
```

## 测试场景

### 场景1：到店自取
1. 添加商品到购物车
2. 进入结算页面
3. 选择"到店自取"
4. 选择支付方式
5. 确认支付
6. 验证订单创建成功

### 场景2：堂食
1. 添加商品到购物车
2. 进入结算页面
3. 选择"堂食"
4. 输入桌号（如：8）
5. 选择支付方式
6. 确认支付
7. 验证订单创建成功

### 场景3：余额支付（余额充足）
1. 确保用户余额 > 订单金额
2. 选择余额支付
3. 确认支付
4. 验证余额扣减成功
5. 验证"我的"页面余额更新

### 场景4：余额支付（余额不足）
1. 确保用户余额 < 订单金额
2. 选择余额支付
3. 看到"余额不足"提示
4. 点击"确定"跳转充值页面
